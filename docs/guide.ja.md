# CatDBを、実際の仕事で試す

CatDBは圏論のデータモデルをHaskellで実装した、1ファイルのローカルDBです。
同梱のRelay Deskで、複数のCSV名簿をまとめ、依頼を担当者に割り当て、共有用一覧を作れます。
ブラウザーは画面を担当し、計算と保存はHaskellが実行します。

Windows版を展開して `Start Relay Desk.cmd` を起動し、表示されたURLを開いてください。
データは同じフォルダーの `desk.catdb` に入ります。保存先を指定する場合は次の形です。

```powershell
.\relay-desk.exe D:\work\desk.catdb --demo
```

親フォルダーは先に作成してください。`--demo` は新規ファイルにだけサンプルを入れます。
実データで始めるなら省略します。既存ファイルを指定すると、続きから使えます。

## 名簿から担当へ

「People & sources」では同じメールアドレスの記録を一人にまとめ、元の氏名・所属・出典を残します。
違うメールでも、同一人物と判断した二つの記録をリンクできます。リンクは取り消せます。
デモのJon B.とJon Bellを結ぶと、6件の記録が4人になり、Engineeringの候補も一人になります。
ここで動くΣは、指定された関係が生成する同値類です。メールを本人性の基準にするのは
アプリ側の方針であり、数学が本人確認をするわけではありません。

「Assignment queue」では、依頼と同じチームに所属する人が候補になります。
Πがチームの一致する組を計算し、利用者が担当を選びます。
担当と依頼のチームが食い違う変更は、画面以外から呼び出してもDBが拒否します。

名簿CSVは `name,email,team`（任意の `id` 列も可）、依頼CSVは `id,title,team` を用意します。
異なる列名も画面で対応づけられます。同じ出典名とIDで再取込みすると更新され、条件違反が
あれば一括で取り消されます。依頼の追加・編集・完了・再開・削除、検索、チーム絞込みにも対応します。

## 共有する範囲を決める

「Public handoff」は未完了の依頼と担当名をCSVまたは構造付きJSONにします。
Δで公開スキーマに読み替えた後、公開記録から到達できる値だけを残します。
メール列を消すだけでなく、使われていない氏名や完了済みタイトルも除きます。
担当名は割当先の元記録の氏名です。タイトルなど、公開対象の内容自体は共有前に確認してください。

「Full backup」は個人情報を含む全データを、開き直せる `.catdb` として保存します。
復元はアプリを終了し、バックアップファイルを引数に指定して起動します。

## このPoCで確かめたいこと

SQLでもこのアプリは作れます。実験の中心は、ビュー・同一視・整合する組を、スキーマ間の
対応と `Σ ⊣ Δ ⊣ Π` という一つの構造から導くことです。由来と普遍写像も取り出せるため、
結果だけでなく変換が保つ関係を調べられます。

有限・非循環スキーマ、メモリ内のデータ、1プロセスの排他接続という制約があります。
SQLite互換でも、本番用途の成熟度を保証する製品でもありません。
