# CatDB Studioの使い方

CatDB Studioは、CatDBのファイルを直接開いて、スキーマ、レコード、変換と由来を扱うローカルGUIです。たとえば、メモから本へ直接進む道と、引用を経由する道を比べ、片方だけを変更すると何が矛盾するかを見られます。画面は日本語です。

## 起動と保存先

Windows配布物を展開し、`Start CatDB Studio.cmd`をダブルクリックします。既定のブラウザーが開きます。開かない場合は、起動ウィンドウに表示されたURLを開いてください。コンパイラーや別のDBサーバーの準備は不要です。`studio-web`と実行ファイルは同じフォルダーに置きます。

「ファイルと書き出し」で、新しいファイル名を入力して作成するか、既存の`.catdb`のフルパスを入力して開きます。ファイル名だけなら、実行ファイルの隣の`data`フォルダーに保存します。開いているファイルのフルパスは同じ画面で確認できます。既存ファイルへの新規作成・バックアップは拒否します。

「ファイルを閉じる」で接続を解放し、同じパスを指定して開き直せます。起動ウィンドウのCtrl+C、またはウィンドウを閉じるとアプリが終了します。確定版はファイルに保存済みです。下書きは保存されません。

起動ごとに、この端末だけで使う接続情報を作ります。表示されたURLから開いてください。別の端末への公開には対応しません。同じファイルを複数のプロセスから同時に開けません。

## 読書メモで一周する

1. 中身に「読書メモ」を選んで、新しく作ります。「Note」の`n1`を選ぶと、`book`と`quote → quoteBook`がどちらも`b1`へ着きます。右の図では終点が一枚に合流します。
2. `n1`の`book`を`b2`へ変更します。下書きの終点は`b2`と`b1`に分かれます。「下書きを確認」はこの矛盾を拒否します。確定した`r1`は変わりません。
3. `n1`の`quote`も`q2`へ変更します。二つの道が`b2`で合流します。「下書きを確認」を通してから「まとめて適用」すると、新しい版になります。関連する参照を勝手に修正することはありません。
4. 「ビューを作る」で入力の版、計算「必要な構造で読み直す（Δ）」、保存済みの対応`cards`、新しいビュー名を選んで保存します。三枚のカードができ、同じ本を指すカードも別々のまま残ります。
5. カードの「由来」から、計算に使った版の元のメモを開けます。その後に元のデータを編集すると、ビューには「古い版」と表示されます。結果は自動では変わりません。「再計算する」で更新します。

見本の文章は架空の表示名です。一般のデータが持つのは行IDと矢印の行き先です。自由な文字列列や数値列を追加する仕組みは、この版にはありません。

## 自分のデータを作る

空のデータベースで「スキーマを作る」を開きます。名前、オブジェクト、矢印を追加し、必要なら共通の始点から二つの道を組み立てて等しいと宣言します。保存すると、空のレコードと同名の編集用の系ができます。既存のスキーマは変更せず、新しい名前で追加します。

各オブジェクトで「行を追加する」を開き、重複しないIDと、出る矢印すべての行き先を指定します。変更は一つの下書きにたまります。関連する行を同じ下書きで追加してから参照先に選べます。行を削除しても参照元は自動削除しません。参照が残る削除は拒否します。行IDの改名は専用操作ではなく、新しい行の追加と参照の付け替え、古い行の削除を明示的にまとめて行います。

表は検索結果の先頭100件を表示します。検索は対象オブジェクトの全行に適用します。「二つの道の約束」は全行の判定数を表示し、行の一覧は検索結果の先頭200件です。保存前のエンジンの確認は表示範囲に限りません。

「版の履歴」から以前の版を読めます。履歴の版や計算結果を編集の出発点にするには、編集用の系として明示的に採用します。同じ系の名前を指定すると、その系の確定版が切り替わり、古い版は残ります。

## 対応と三つの計算

「保存した対応」から新しい対応を作ります。Fの始点と終点のスキーマを選び、各オブジェクトの像を指定します。各矢印について、対応先で合成できる道を組み立てます。空の道を使う場合も明示的に指定します。保存時には、スキーマのパス等式を保つことまで確認します。

| 画面の計算 | 必要な対応の向き | できるものと由来 |
|---|---|---|
| 必要な構造で読み直す（Δ） | F : 出力 → 入力 | 元の行を別の構造で読む。`PullRef`で元の版の行へ戻る |
| 宣言した同一視でまとめる（Σ） | F : 入力 → 出力 | 輸送された行の同値類。`SigmaClass`で元の行と道を確認する |
| 関係がそろう組を集める（Π） | F : 入力 → 出力 | 矢印の関係を満たす族。`PiFamily`で各成分を確認する。空の族も明示する |

「対応の見本」の`by-key`をΣとΠの両方に使うと、同じキーでまとまる二つの同値類と、矢印の関係を満たす二つの組を比べられます。Σは実在物の同一性を推定せず、Πは内容の真実性を証明しません。等式で同じ射になる道は、表記が違っても同じ像です。

行の右側から「この行と行き先から部分を作る」を選ぶと、矢印に沿って閉じた部分を保存できます。各行の`GeneratedRef`は元の版を指します。

入力が編集用の系の現在の版なら、ビューはその系に結び付きます。古い版を選んだ場合はその版に固定します。取り込んだ複数段のビューは保存・閲覧できますが、Studioの一段の再計算では置き換えません。各段を確認し、新しいビューとして計算します。

## 既存ファイルと書き出し

カタログのない従来の`.catdb`は読み取り用に開きます。編集する場合は別の保存先を指定して取り込みます。元のファイルは置き換えません。既存のネイティブカタログも開けます。アプリのデータとカタログが同居するファイルでは、外側のアプリデータを保持します。Studio内の版を編集しても、外側の別アプリのデータを書き換えることはありません。

バックアップの`.catdb`は、すべての確定版、対応、ビューと由来を含みます。ダウンロードしたファイルを通常の「開く」で復元できます。定義とデータのJSON書き出しはHaskellでの再利用用です。[実行例](../examples/StudioExport.hs)もあります。JSONの権威的なサイドカーファイルは作りません。

有限・非循環のスキーマ、メモリに収まるデータ、一つのプロセスからの利用が対象です。SQL、NULL、汎用の値の代数、再帰スキーマ、索引、最適化器はありません。計算量とカタログ全履歴にはライブラリの`defaultBudget`を使い、純粋な計算は20秒で打ち切ります。計算中は取り消せます。保存処理に入った後の確定は取り消せません。上限を超えた場合に部分結果を成功として保存することはありません。[正確な制限](../STATUS.md)と[ネイティブカタログ](native-memory.md)を参照してください。
