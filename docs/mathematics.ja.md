# 経路、商集合、整合する組からDBを作る

この実装では、ビュー・統合・結合を別々の特別なエンジンにしていない。スキーマ対応 `F` を読み、各対象で集合を構成し、その集合間の関数を構成する。

## 経路の等しさを先に決める

有限の非循環グラフから自由圏を作り、宣言した経路等式が生成する合同関係で割る。すべての経路を列挙し、各等式の前後に置ける経路を付けた関係を作り、同値閉包を取る。

`Schema.schema` がこの処理を行う。等式を「左から右への書換え規則」にしていないので、規則の向きや探索回数で等しさが変わらない。この対象範囲では経路の等価性を正確に決定できる。非循環という境界は、この有限で明確な意味論を保つために選んだ。

インスタンス `I : C → FinSet` は対象ごとの有限集合と、生成射ごとの全域関数を持つ。`instanceOf` は全域性、参照先、経路等式を検査する。多対多関係は辺の対象と二つの射で表せる。NULLを暗黙の例外にはしない。

## 一つの対応が三つの操作を決める

スキーマ対応は関手 `F : C → D`。対象を対象へ、生成射を経路へ写し、Cの経路等式がDでも成立することを検査する。データがたまたま等しいことを、スキーマの等式の証明には使わない。

`Δ_F J = J ∘ F` は前合成そのもの。元の行IDを保ち、射に指定された経路を評価する。対応の合成 `G ∘ F` に対して `Δ_(G∘F) = Δ_F ∘ Δ_G` となる。

`Σ_F I` の対象 `d` における要素は、次のトークンを同一視した同値類である。

```text
(c, p : F(c) → d, x ∈ I(c))

(c, F(a);q, x) ~ (c', q, I(a)(x))     a : c → c'
```

生成射について関係を課せば、合成射についても成立する。Dの射 `b : d → d'` は `[c,p,x]` を `[c,p;b,x]` に写す。これがコンマ圏 `(F ↓ d)` 上の余極限、左Kan拡張である。

`Π_F I` の対象 `d` における要素は、各 `(c,p : d → F(c))` に `x_(c,p) ∈ I(c)` を選び、次を満たす組である。

```text
I(a)(x_(c,p)) = x_(c',p;F(a))        a : c → c'
```

Dの射 `b : d → d'` は、組の `(c,q)` 成分を元の `(c,b;q)` 成分から取り出す。これが `(d ↓ F)` 上の極限、右Kan拡張である。空の図式についても、余極限は空集合、極限は一元集合になる。

## 普遍性を呼び出せるAPIにする

結果だけを返すなら、同じ入出力を持つ個別処理とも区別がつきにくい。そこで、この実装は普遍写像と一意な因子化も返す。

```text
sigmaUnit   : I → Δ_F(Σ_F I)
sigmaFactor : (I → Δ_F J) → (Σ_F I → J)

piCounit    : Δ_F(Π_F I) → I
piFactor    : (Δ_F J → I) → (J → Π_F I)
```

`sigmaFactor` は `[c,p,x] ↦ J(p)(h_c(x))`。`h` の自然性により、同値類の代表元を替えても値が変わらない。

`piFactor` は `y ↦ (h_c(J(p)(y)))_(c,p)`。自然性により、この組は必要な整合条件を満たす。

逆方向の対応は、`Δ` と単位／余単位の合成で得られる。二つの対応が互いに逆であることが

```text
Nat_D(Σ_F I, J) ≅ Nat_C(I, Δ_F J)
Nat_C(Δ_F J, I) ≅ Nat_D(J, Π_F I)
```

を与える。ここに実装の中心を置いた。`sigmaNatural` と `piNatural` も、この因子化から導いている。特殊な行集合演算を増やすより、一つの意味論から複数の操作を作れる。

## 実用部分との境界

自然変換は構造を保存する写像であり、任意の更新と同義ではない。通常の編集は純粋な `edit` で行い、トランザクションの終わりにインスタンスの条件を再検査する。`select` は指定した対象で残す要素を選び、参照が壊れる側の要素を除去して、条件を満たす最大の部分関手を作る。データ削除の暗黙のcascadeには使わない。

永続化はこの純粋な意味論の外側に置く。数学が保証する構造保存と、OSが担当するflushやロックを混同しない。フルの型付き代数・循環スキーマ・SQLとの実用比較は今後の研究課題であり、このPoCの成功から優位性を一般化しない。
